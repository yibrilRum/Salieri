6. Residual Data After Deletion

After deleting an instrument, its notes sometimes remained visible when re-added with the same name.

Root cause: music21's bidirectional site tracking — elements weren’t fully unlinked from the Score’s site registry.

This left dangling references and caused “entry not stored in Sites object” errors.

🧨 Current Issue (Unresolved)
[BUG] Stream corruption after part deletion and re-addition
Symptoms

After deleting an instrument part and adding another with the same or different name:

Old notes sometimes persist.

Following edits trigger:

Error deleting instrument: an entry for this object (<music21.stream.Score ...>) is not stored in this Sites object


On subsequent operations, KeyError occurs during sortTuple inside Music21’s internal stream sort.

Repro Steps

Create and save a score with one part (e.g., Violin I).

Add notes, restify, or edit multiple times.

Save project.

Delete the part (Menu → Delete Instrument Part).

Add a new part (Violin II).

Attempt to delete or view parts again.
→ Crashes or “corrupted file” warnings.

Root Cause

score.parts.remove(part) acts on a StreamIterator, not a real Stream.

This leaves orphaned Note objects referencing a deleted site.

The next recursive traversal or save triggers internal corruption errors.

Proposed Fix
if part in score.parts.stream():
    score.remove(part, recurse=False)
    for el in list(part.recurse()):
        try:
            el.sites.removeBySite(part)
        except Exception:
            pass
    part.clear()

Validation

Add:

def validate_score(score):
    for part in score.parts:
        for el in part.recurse():
            if not score in el.sites:
                print(f"⚠️ Orphan element: {el}")
                return False
    return True
